# MCP 2026 Engineering Principles

**Created by School of AI**

1. Prefer self-describing stateless protocol calls.
2. Make application state explicit.
3. Route and authorize on method/name metadata where appropriate.
4. Treat tool selection and tool authorization as separate decisions.
5. Minimize scopes.
6. Validate issuer and audience.
7. Use Tasks for durable long-running work.
8. Use MRTR for input required during an active call.
9. Cache catalogs using server-provided hints.
10. Use extensions through explicit capability negotiation.
11. Assess third-party MCP servers as supply-chain dependencies.
12. Centralize gateway policy when many servers need consistent control.
13. Trace identity, method, name, server and outcome.
14. Track deprecations and SDK versions.
15. Keep business-critical controls outside the LLM.
